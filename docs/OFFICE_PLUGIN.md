# Office / WPS Citation Add-in

LiteratureX includes a local citation add-in for **WPS Writer** and **Microsoft Word**. It lets users search the local LiteratureX library from a task pane and insert numeric or author-year citations plus a bibliography.

## Architecture

```
WPS Writer                          Microsoft Word
  │ ribbon button                      │ Task Pane (Office.js)
  ▼                                    ▼
Local taskpane.html (file://)       https://127.0.0.1:47832/office/index.html
  │ fetch + token                      │ fetch (same origin)
  ▼                                    ▼
┌─────────────────────────────────────────────────────────────┐
│ PluginService (main process)                                │
│  HTTP  127.0.0.1:47831  ── WPS task pane + REST API         │
│  HTTPS 127.0.0.1:47832  ── Word task pane + REST API        │
│  token-protected: /api/plugin/status|search|references      │
│  data source: ArticleRepo (library scope only)              │
└─────────────────────────────────────────────────────────────┘
```

- Both task panes use the same `resources/office-plugin/shared/app.js` UI/logic.
- The WPS add-in is installed into `%APPDATA%\kingsoft\wps\jsaddons\LiteratureX_<version>` and registered in `publish.xml`.
- The Word add-in is a task-pane manifest generated at `%APPDATA%\LiteratureX\office-addin\manifest.xml`. It is served over local HTTPS because Office add-ins require HTTPS; a self-signed localhost certificate is generated and trusted on explicit user action.
- API requests require `X-LiteratureX-Token`, a random token stored in `application_settings` (`plugin_token`). It is injected into the Word page and written into the WPS add-in `config.js` at install time.
- No document content is sent to external services. Office.js is loaded from Microsoft's CDN for Word; the reference data stays local.

## WPS add-in files

```
resources/office-plugin/wps/
  index.html          entry loaded by WPS
  main.js             loads config + ribbon scripts
  ribbon.xml          "LiteratureX" tab and button
  manifest.xml        WPS plugin metadata
  js/config.js        token/apiBase (rewritten at install)
  js/ribbon.js        CreateTaskPane / ribbon callbacks
  ui/taskpane.html    local task pane
  images/icon.svg
resources/office-plugin/shared/
  app.js              search, citation storage, insertion bridges
  app.css
  icon-32.png / icon-80.png
```

The installer copies the WPS files plus `shared/` into the versioned add-in folder, injects the current token and HTTP port, and merges one `<jsplugin>` entry into `publish.xml` without removing other add-ins.

## Word add-in files

- Manifest: generated per install with `SourceLocation=https://127.0.0.1:47832/office/index.html`.
- Task pane HTML: served by `PluginService`, injects token + Office.js CDN + shared `app.js`.
- Certificate: generated by `selfsigned` with SANs `DNS:localhost`, `IP:127.0.0.1`, `IP:::1`; private key stored under `%APPDATA%\LiteratureX\office-addin\certs` (mode 600). Trust is installed into the **current user** Root store via `certutil -user -addstore`.
- Sideload: Word → Insert → Get Add-ins → My Add-ins → Upload My Add-in → manifest.xml.

## Citation behavior

- Numeric: `[1]`, `[1,2]`; numbering is first-citation order.
- Author-year: `(Ji et al., 2024; Lee et al., 2023)`.
- Bibliography entries are generated from the same library metadata (authors, title, journal, year, volume/issue/pages, DOI).
- Cited IDs are stored in Word document settings (`Office.context.document.settings`) or WPS document variables; a local-storage fallback is used in preview mode.
- Manual host bridges:
  - Word: `Word.run` → `getSelection().insertText`; bibliography via `body.insertParagraph`.
  - WPS: `window.Application.Selection.TypeText`; bibliography via `ActiveDocument.Content.InsertAfter`.

## Security notes

- Servers bind only to `127.0.0.1`; token required for all API routes.
- CORS allows the local add-in origins; private-network preflight headers are provided for WPS `file://` → `http://127.0.0.1` requests.
- The trust operation is only attempted after an explicit confirmation in Settings. If it fails, the exact `certutil` command and certificate path are shown.
- Uninstalling the WPS add-in removes only the LiteratureX folder/manifest entry. The Word certificate remains in the user store; users can remove it manually with `certutil -user -delstore Root <thumbprint>`.

## Testing status

- PluginService is unit/integration tested: HTTP API + token, search/reference formatting data, WPS install/merge/uninstall in a temporary addons directory, and Word certificate/manifest generation without trusting the certificate.
- The WPS add-in package install path and file layout were validated against the WPS JS add-in (`wpsjs`) template. Full ribbon/task-pane interaction requires restarting WPS interactively.
- Microsoft Word is not installed in the build environment, so the Word manifest/HTTPS flow is implemented and smoke-checked at the service level but not end-to-end in Word.
